# 敵対的コードレビュー(コンテキストあり): Region Checker for AWS Console

対象: `manifest.json` / `content.js` / `content.css` / `README.md`(仕様 `ideas/20261008-aws-region-checker.md`、実装説明 `docs/20261008-implementation.md` を参照)
日付: 2026-10-08

## 結論

- 仕様の中心である「リージョンが変わったら再表示」は、実運用の経路(リージョン切替=オリジン切替)では **各リージョン 1 回きりしか成立しない**(H1)。実装説明は既知の制約としているが、README は無条件に「再表示します」と書いている。
- バナーが「出るべき場面で見えない」経路が 3 つある(M1 ボタンが非表示、M2 CSS 未適用時のフォールバック、L5 拡張コンテキスト無効化)。
- セキュリティ節の主張(外部通信なし、HTML 解釈 API 不使用、表示値は正規表現で制限)はコードで裏が取れた。XSS・情報漏えい・MutationObserver の自己ループは崩せなかった。ただし表示値に長さ上限がなく、URL で文言を差し込める(L2)。
- 指摘数: 高 1 / 中 4 / 低 11。

## 検証方法と限界

- 静的読解と、Node `vm` 上の偽 DOM で `content.js` をそのまま実行するハーネス(`review-adv-harness.js`、本レポートと同じディレクトリ)。各指摘の「T番号」はその出力。
- 実ブラウザ・実 AWS コンソールでは未検証。AWS コンソールの実 DOM・CSP・URL 体系に依存する指摘は **推測** と明記した。
- 「確認済み」と書いたものは、コードの読解またはハーネス出力で裏が取れたもの。

## 重大度: 高

### H1. リージョンを往復すると二度と再表示されない(仕様「リージョンが変わったら再表示」の実質未達)

- 場所: `content.js:48-63`(sessionStorage)、`content.js:114`(確認済みなら消す)、`README.md:11-12`
- シナリオ(T8 で確認済み):
  1. 同じタブで東京 `ap-northeast-1.console.aws.amazon.com` を開き `ap-northeast-1` と入力 → 消える
  2. `us-east-1` に切替 → 表示 → `us-east-1` と入力 → 消える
  3. 東京に戻る → **表示されない**。以後、東京とバージニアを何度往復しても表示されない
- 根拠: `sessionStorage` はオリジン単位。コンソールのリージョン切替はホスト名(=オリジン)が変わるので、各オリジンに「自分のリージョンは確認済み」が残り続ける。`update()` は `region === getConfirmed()` で無条件に消す。
- 影響: 仕様の例(東京 → us-east-1 で再表示)は初回だけ通る。この拡張が狙う「本番と検証のリージョンを同じタブで行き来して取り違える」場面では、各リージョンを 1 回確認した後は何も出ない。
- 実装説明との関係: `docs/20261008-implementation.md:57` は既知の制約として書いている。ただし README は「リージョンが変わると再表示します」(`README.md:11`)と無条件に書いており、利用者には伝わらない。
- 追加の非対称(T9 で確認済み): 同一オリジン内では保存が 1 件だけなので、`us-east-1` の EC2 と IAM(Global)を行き来するたびに毎回再表示される。別オリジンは「二度と出ない」、同一オリジンは「毎回出る」で、挙動が逆方向にずれている。
- 補足: 確認済みに有効期限がなく、タブの複製やブラウザのセッション復元でも `sessionStorage` は引き継がれる。README の「タブを閉じると消えます」(`README.md:16`)は、復元したタブには当てはまらない(ブラウザ仕様に基づく推測、未検証)。

## 重大度: 中

### M1. リージョンボタンが DOM にあって非表示のとき、バナーも見えない

- 場所: `content.js:99-105`
- シナリオ: ナビが狭い画面幅で項目を畳む、全画面表示でナビごと隠す、などでボタンが `display: none` の祖先の中に残っている状態 → `querySelector` はボタンを返す → バナーはその隣(同じ非表示コンテナ内)に挿入され、`data-fallback` は外れる → 画面には何も出ない。
- 根拠: `place()` はボタンの存在だけを見ており、可視性(`getClientRects().length` など)を確認していない。フォールバックに切り替わるのは「ボタンが無い」か「挿入 20 回到達」のときだけ。
- 確度: ロジックは確認済み。AWS のナビが実際にボタンを DOM に残したまま隠すかは **推測**(実 DOM 未確認)。

### M2. CSS が未適用の間、フォールバック表示は画面右上に出ない

- 場所: `content.js:69-71`、`content.js:106-109`、`content.css:11-17`、`docs/20261008-implementation.md:138`
- シナリオ: リージョンボタンが見つからないページで、`content.css` の読み込みが失敗または未完了 → `:host([data-fallback])` の `position: fixed` が効かない → バナーは `document.body` の末尾に通常フローで置かれ、ページ最下部(スクロールしないと見えない位置)に出る。
- 根拠: 固定配置は Shadow DOM 内の `<link>` で読む CSS にだけ書かれている。ホスト要素自体にはインラインの位置指定がない。
- 実装説明との矛盾: 「CSP で読めなければ無装飾で表示される(機能は動く)」とあるが、フォールバック時は「表示位置」も CSS 依存なので、実質見えない。
- 確度: 読み込み完了前の一瞬に起きることは確認済み(`<link>` は非同期)。ページの CSP が拡張同梱 CSS を止めるかは **推測**(実装説明も未確認としている。Firefox で特に要確認)。

### M3. グローバル判定が固定一覧とボタン文言 2 種に依存し、us-east-1 と誤表示する

- 場所: `content.js:8-17`、`content.js:35-39`
- シナリオ A(T10 で確認済み): 一覧にないグローバルサービス(例: `us-east-1.console.aws.amazon.com/support/home`)を開く → ナビ描画前は `us-east-1` と表示 → ボタンが描画されて初めて `Global` に変わる。`us-east-1` が確認済みなら、描画前は何も出ない。
- シナリオ B(T10 で確認済み): コンソールの表示言語が日本語・英語以外で、ボタン文言が `Global` / `グローバル` でない → 一覧外のグローバルサービスは `us-east-1` のまま。
- シナリオ C: ボタンのセレクタが外れている、または `textContent` に余分な文字(アイコンの代替テキストなど)が混ざる → 完全一致が成立せず同上。
- 根拠: `GLOBAL_LABELS` は完全一致で 2 語のみ。`GLOBAL_SERVICES` は 7 件のみ。
- 確度: ロジックは確認済み。他言語での実際のボタン文言と、一覧外サービスの URL は **推測**。

### M4. ナビへの挿入回数が累計で、長時間のタブは恒久的に固定表示へ落ちる

- 場所: `content.js:20`、`content.js:27`、`content.js:99-104`、`content.css:11-16`
- シナリオ(T4 で確認済み): SPA のまま長時間使い、ナビの再描画やボタン直前への要素挿入が累計 20 回起きる → `navInserts` はリセットされないので、以後ボタンがあっても `position: fixed; top: 56px; right: 16px; z-index: 2147483647` で出る。
- 根拠: カウンタはページ読み込み単位の累計で、時間窓も成功時のリセットもない。`host.nextSibling !== button` は、間に別ノードが 1 つ入るだけでも「外れた」と数える。
- 影響: 「無限ループの打ち切り」が、正常な再描画の積み重ねでも発動する。固定表示は最大の `z-index` でページ右上の操作部品やモーダルに重なる(どの部品に重なるかは **推測**)。

## 重大度: 低

### L1. `sessionStorage.setItem` だけが失敗すると、正しく入力してもバナーが消えない

- 場所: `content.js:48-63`
- シナリオ(T1 で確認済み): 容量超過などで `setItem` が例外、`getItem` は成功 → `setConfirmed` は `confirmedFallback` に入れるが、`getConfirmed` は `sessionStorage` の `null` を返す → 正解を入力しても残り続ける。
- 根拠: 代替値を読むのは `getItem` が例外を投げたときだけ。書き込み失敗と読み出し成功の組み合わせを想定していない。

### L2. 表示するリージョン文字列に長さ上限がなく、URL で文言を差し込める

- 場所: `content.js:5`、`content.js:43`、`content.js:122`、`content.css:29`
- シナリオ(T2 で確認済み): ホスト名にリージョンを含まないホスト(`health.` / `s3.` / 素の `console.aws.amazon.com`)へのリンクに `?region=xx-your-account-is-locked-call-support-...-1` を付ける → 正規表現を通り、1,400 文字超の英字ハイフン列がバナーに出る。`white-space: nowrap` なのでナビを横に押し広げる。`?region=zz-fake-9` のような実在しないコードもそのまま出る。
- 根拠: `(-[a-z]+)+` は繰り返し回数も語長も無制限。実在リージョンの一覧照合はない。
- 限界: 使えるのは英小文字とハイフンと末尾の数字だけで、スクリプト注入にはならない。AWS 側がリダイレクトやエラーにする可能性があり、実際に表示が残るかは **推測**。
- 実装説明との関係: 「任意文字列をそのまま表示することはない」(`docs:39`)は、文字種については正しいが内容と長さについては言い過ぎ。

### L3. ホスト名とクエリが食い違うとホスト名を表示する

- 場所: `content.js:41-45`
- シナリオ(T3 で確認済み): `https://us-east-1.console.aws.amazon.com/s3/buckets/b?region=ap-northeast-1` → `us-east-1` と表示。
- 確度: この形の URL が実際に存在し、操作対象がクエリ側のリージョンになるかは **推測**。存在するなら、操作対象と異なるリージョンを確認させることになる。

### L4. キーボードイベントの伝播停止は、キャプチャ段階のショートカットを止めない

- 場所: `content.js:89-92`
- シナリオ: コンソール側が `window` / `document` にキャプチャ段階で `keydown` を登録している → 入力欄のリスナーより先に走る。Shadow Root が `closed` なので、ページから見たイベントの `target` はホストの `div` になり、「入力欄ではショートカットを無効にする」というページ側の判定も効かない。
- 確度: イベント仕様としては確認済み。AWS コンソールがキャプチャ段階で登録しているかは **推測**。

### L5. 拡張の更新・再読み込み後、古いタブでバナーが出なくなる

- 場所: `content.js:65-71`、`content.js:119-125`
- シナリオ(T6 で確認済み): バナー未生成のタブ(確認済みで非表示)で拡張コンテキストが無効になり、`chrome.runtime.getURL` が例外を投げる → `host` は代入済み、`label` は `null` のまま → 次の `update()` で `shownRegion` を更新した直後に `TypeError` → その次からは `region === shownRegion` で文言更新を飛ばし、**中身が空のホスト** を配置して終わる。エラーは 1 回だけで、以後は無言。
- 確度: 失敗後の状態遷移は確認済み。無効化後に `getURL` が投げるかは Chrome の挙動に基づく **推測**。
- 関連(推測): Firefox は拡張の更新・再読み込み時に既存タブへコンテンツスクリプトを再注入する。古いホスト要素は DOM に残るので、反応しないバナーと新しいバナーが 2 つ並ぶ可能性がある。既存ホストの掃除や二重注入の防止がない。

### L6. body 直下のフォールバックは再挿入に上限がない

- 場所: `content.js:106-108`
- シナリオ(T5 で確認済み): ページ側が `body` 直下の未知の要素を消し続ける → 500 回消して 500 回再挿入。ナビ側の上限 20 回はこの経路に効かない。
- 限界: 200ms の間引きがあるので最大でも毎秒 5 回。暴走にはならない。

### L7. 入力照合の抜け

- 場所: `content.js:84-88`
- 全角入力(T7 で確認済み): 日本語 IME が有効のまま `ａｐ－ｎｏｒｔｈｅａｓｔ－１` と打っても一致しない(NFKC 正規化なし)。利用者が日本語話者の想定なので踏みやすい。
- コピー&ペースト: ラベルは選択可能で、貼り付けでも `input` イベントが出る。「入力させて意識させる」は選択と貼り付けで迂回できる(設計判断の範囲だが、目的は弱まる)。

### L8. `:host` のスタイルはページ側の規則に負ける

- 場所: `content.css:3-8`
- シナリオ: ナビの CSS が子要素を構造で指定している(例: `nav > div:not(...) { display: none }`)→ ホストの `div` に当たり、`:host` の `display: inline-flex` より優先される。
- 根拠: CSS の仕様上、外側の文書の規則は `:host` の通常宣言より優先される。`all: initial` が切るのは継承だけ。
- 確度: AWS のナビに該当する規則があるかは **推測**。

### L9. プライバシー・権限の記述とのずれ

- `README.md:39`「アカウント ID は読みません。参照するのは URL のホスト名…」: マルチセッション時のホスト名にはアカウント ID を含むラベルが付く(`docs:122` 自身が認めている)。保存も表示もしないのは確認済みだが、「読まない」は言い過ぎ。
- `manifest.json:12-17`: 仕様の構成は「matches と permissions なし」だけで、`web_accessible_resources` は仕様にない追加。権限ではないが、AWS コンソール上のスクリプトから拡張の導入有無を検知できる(`docs:96` に記載あり)。`sessionStorage` のキー `region-checker:confirmed` でも検知できる。

### L10. manifest の細部

- `manifest.json:21-24`: `data_collection_permissions` は `strict_min_version: 127.0` より新しい Firefox で導入されたキーのはずで、AMO の検証で警告になる可能性がある(**推測**、未確認)。
- アイコン未同梱(`docs:105` に記載あり)。ストア提出は現状できない。
- Chrome は `browser_specific_settings` を未知のキーとして警告表示する可能性がある(**推測**。動作には影響しない)。

### L11. 「消すにはリージョンを入力」がプレースホルダだけ

- 場所: `content.js:79-80`
- 仕様は「現在のリージョン: … / 消すにはリージョンを入力」をバナーに表示するとしている。実装はプレースホルダなので、1 文字打つと消える。`role` や `aria-live` もなく、スクリーンリーダーには出現が通知されない。

## 崩せなかった点

| 攻めた点 | 結果 |
| --- | --- |
| 外部通信・HTML 解釈 API | `content.js` に `fetch` / XHR / WebSocket / `innerHTML` 系 / `eval` / Cookie / `localStorage` / meta 参照なし(grep 該当なし)。読み込むのは同梱 CSS だけ |
| URL やボタン文言からの XSS | 表示は `textContent` のみ、値は正規表現一致か固定の `Global`。崩せない |
| MutationObserver の自己ループ | 安定状態では `update()` が DOM を変更しない。Shadow DOM 内の変更と属性変更は監視対象外。ナビ側の取り合いは 20 回で止まる(T4)。残るのは L6 の毎秒 5 回上限の再挿入だけ |
| 性能劣化 | DOM 変化が続いても `update()` は 200ms に 1 回、`querySelector` 2 回。実測はしていないが、問題になる規模とは考えにくい(**推測**) |
| 正規表現と実在リージョン | 対象ドメインの商用リージョンはすべて一致。不一致は `eusc-de-east-1` だけで、別ドメインのため対象外(T11) |
| ホスト名ラベルの誤検知 | `console` / `aws` / `s3` / アカウント ID 付きラベルはどれも一致しない(T11)。マルチセッション形式からリージョンだけ取れる |
| パス細工で `Global` と誤判定させる | `..` はブラウザが正規化する。先頭セグメントが一覧と一致する別のリージョナルサービスは見つけられなかった |
| ページ側スクリプトからバナー内部を操作 | Shadow Root は `closed`、コンテンツスクリプトは隔離された実行環境。ページが `attachShadow` を差し替えても影響しない。残る手段は `sessionStorage` の書き換え(`docs:123` に記載済み)と、ホスト要素の削除・非表示だけ |
| `matches` の範囲 | `https://*.console.aws.amazon.com/*` のみ。`all_frames` なしで最上位フレーム限定。過剰な注入はない |
| CVSS 0〜3.9 の主張 | 機密性への影響は見つからない。最悪でも表示の欠落・誤表示で、主張の範囲に収まると判断 |
| Firefox の `chrome.*` / MV3 の `web_accessible_resources.matches` | どちらも Firefox が対応している前提で矛盾は見つからない(実機未検証) |

## 未検証のまま残るもの

- 実ブラウザ(Chrome / Firefox)と実 AWS コンソールでの動作すべて
- セレクタ `[data-testid="awsc-nav-regions-menu-button"]` の実在とボタン文言
- ページ CSP 下での同梱 CSS の読み込み(M2 の前提)
- Firefox 127 でのホストアクセス付与、`data_collection_permissions` の扱い
