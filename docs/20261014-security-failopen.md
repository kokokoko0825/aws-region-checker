## 指摘

### 1. [中] ホスト名のリージョンと操作対象のリージョンが食い違うと host 側を表示する

- CVSS: `CVSS:3.1/AV:L/AC:L/PR:N/UI:R/S:U/C:N/I:L/A:N` = 3.3。攻撃者不要。
- 根拠: `content.js:74-78`(ホスト名 → `region` クエリ → ボタン文言の順で最初に見つかったものを返す)
- 内容: ホスト名にリージョンがあれば `region` クエリは読まれない。コンソールにはホストのリージョンと操作対象のリージョンが別になる画面がある。代表は S3 で、URL は `https://us-east-1.console.aws.amazon.com/s3/buckets/<bucket>?region=ap-northeast-1` の形になり、`region` がバケットのリージョンを指す。この画面でバナーは `us-east-1` を示す。`us-east-1` を確認済みならバナーは出ないまま、東京のバケットを操作できる。
- 再現: ハーネスで `location` を `https://us-east-1.console.aws.amazon.com/s3/buckets/b?region=ap-northeast-1` にして実行 → ラベルは「現在のリージョン: us-east-1」。
- 修正案: ホスト名と `region` クエリの両方が取れて値が違うときは、両方を表示する(例: 「コンソール: us-east-1 / 対象: ap-northeast-1」)か、少なくとも確認済み扱いにせずバナーを出す。確認の鍵も両方の組にする。
- 確度: 判定ロジックは実際に走らせて確かめた。S3 の URL 形式と、同様の画面が他サービスにどれだけあるかは実コンソールでの確認が必要。

### 2. [中] ホスト名の最初に合致したラベルを採用するため、サブドメインで偽装できる

- CVSS: `CVSS:3.1/AV:N/AC:H/PR:N/UI:R/S:U/C:N/I:L/A:N` = 3.1。攻撃者が必要(細工したリンクを踏ませる)。AWS が該当ホスト名でコンソールを配信する場合は AC:L で 4.3。
- 根拠: `content.js:65`(`parts.find`)、`content.js:75`(`location.hostname.split(".")` を左から走査)、`manifest.json:13`(`*.console.aws.amazon.com` は任意の深さのサブドメインに一致)
- 内容: `ap-northeast-1.us-east-1.console.aws.amazon.com` では左端の `ap-northeast-1` が採用される。実際のリージョンは `console.aws.amazon.com` の直前のラベル(`us-east-1`)。マルチセッションは `<アカウントID>-<乱数>.<region>.console.aws.amazon.com` の形でリージョンの左に任意のラベルを取るため、AWS はこの位置にワイルドカード DNS と証明書を持っている可能性が高い。配信されるなら、利用者が `ap-northeast-1` を確認済みのタブでは `us-east-1` のコンソールがバナーなしで開く。
- 再現: ハーネスで `https://ap-northeast-1.us-east-1.console.aws.amazon.com/ec2/home` → 「現在のリージョン: ap-northeast-1」。正規のマルチセッション形式 `123456789012-abcd1234.us-east-1.console.aws.amazon.com` は左端のラベルが数字始まりで正規表現に合わず、正しく `us-east-1` になる。
- 修正案: 左から探さず、`console.aws.amazon.com` の直前のラベルだけを見る。

  ```js
  const m = /(?:^|\.)([a-z0-9-]+)\.console\.aws\.amazon\.com$/.exec(location.hostname);
  const hostRegion = m && REGION_RE.test(m[1]) ? m[1] : null;
  ```

- 確度: ラベルの採用順は実際に走らせて確かめた。AWS がこのホスト名を解決・配信するか、配信時にリダイレクトされるかは実コンソールでの確認が必要(DNS はサンドボックスの制限で引けなかった)。

### 3. [中] リージョンを判定できないページでは何も表示しない

- CVSS: `CVSS:3.1/AV:L/AC:H/PR:N/UI:R/S:U/C:N/I:L/A:N` = 2.5。攻撃者不要。
- 根拠: `content.js:230-234`(`!region` のとき `host?.remove()` して終了)、`content.js:10` と `background.js:8`(正規表現)
- 内容: 対象ページにいるのに判定できなかった場合と、確認済みの場合が同じ「バナーなし」になる。利用者は区別できない。該当するのは次のとおり。
  - ホスト名にもクエリにもリージョンがないページ。例: `console.aws.amazon.com/console/home`(リダイレクト前)、`support.console.aws.amazon.com/...`。
  - 正規表現 `^[a-z]{2}(-[a-z]+)+-\d+$` に合わないリージョン名。現行で合わないのは `eusc-de-east-1`(先頭が 4 文字)の 1 件。将来 3 文字以上の接頭辞が増えると同じことが起きる。
- 再現: ハーネスで `https://console.aws.amazon.com/console/home` と `https://support.console.aws.amazon.com/support/home` → バナーなし。`https://eusc-de-east-1.console.aws.amazon.com/ec2/home`(仮のホスト)→ バナーなし。既知のリージョン名 21 件を正規表現に通すと、不一致は `eusc-de-east-1` だけ。
- 修正案: 対象ホストで判定できないときは「リージョン不明」のバナーを出す(入力で消す対象がないので、閉じるボタンだけにするか、そのページの間だけ消せるようにする)。正規表現の先頭は `[a-z]{2,}` に緩める(`content.js` と `background.js` の両方)。
- 確度: 挙動は実際に走らせて確かめた。リージョンなしホストに操作可能な画面が残っているかは実コンソールでの確認が必要。`eusc-de-east-1` は一致パターン外の別ドメインと思われるので、現状では #10 と合わせた将来の問題。

### 4. [中] バナーの位置を画面内に丸めない

- CVSS: `CVSS:3.1/AV:L/AC:H/PR:N/UI:R/S:U/C:N/I:L/A:N` = 2.5。攻撃者不要。
- 根拠: `content.js:205-209`(`navBottom` / `toolbar.top` をそのまま `top` に使う)、`content.js:215`、`content.js:259-261`(`scroll` を監視していない)
- 内容: `top` はツールバーまたはナビバーの `getBoundingClientRect()` の値をそのまま使う。これらがスクロールで画面外に出るレイアウトでは、次の `update()` でバナーも画面外に置かれる。逆に、スクロールだけでは `update()` が走らないので、位置は直前の DOM 変化時点のまま残る。どちらになるかは DOM 変化のタイミング次第で、利用者からは「出たり出なかったりする」ように見える。
- 再現: ハーネスでツールバーの矩形を `top: -480` にする → ホストの `top` は `-480px`。ナビバー下端を `-260` にする → `top` は `-260px`。リージョンボタンが左端(`right: 20`、画面幅 400)にあると `right: 380px` / `max-width: 12px` になり、実質読めない幅になる。
- 修正案: `top` を `Math.max(0, …)` で下限 0 に丸め、ボタンやツールバーの矩形が画面外なら `FALLBACK_TOP` / `FALLBACK_RIGHT` を使う。`max-width` が一定値(例: 200px)を下回るときも `FALLBACK_RIGHT` に切り替える。
- 確度: 計算結果は実際に走らせて確かめた。現行コンソールでツールバーやナビが実際に画面外へスクロールするページがあるかは実コンソールでの確認が必要(どちらも固定表示なら発生しない)。

### 5. [低] リージョンのないホストでは `?region=` を検証せずに表示する

- CVSS: `CVSS:3.1/AV:N/AC:H/PR:N/UI:R/S:U/C:N/I:L/A:N` = 3.1。攻撃者が必要(細工したリンク)。
- 根拠: `content.js:76`(クエリがボタン文言より優先)、`content.js:10`(形式だけの検査)
- 内容: ホスト名にリージョンがないとき、`region` クエリの値が正規表現に合えばそのまま表示する。サーバーがその値を採用したかは見ていない。実在しないリージョン名も表示する。
- 再現: ハーネスで `https://console.aws.amazon.com/ec2/home?region=eu-west-1`、ボタン文言 `us-east-1` → 「現在のリージョン: eu-west-1」。`?region=zz-fake-9` → 「現在のリージョン: zz-fake-9」。
- 成立しない範囲: ホスト名にリージョンがあるページでは、クエリもボタン文言も結果を変えられない(`us-east-1` のホストに `?region=ap-northeast-1` やボタン文言 `ap-northeast-1` を与えても `us-east-1` のまま)。この場合に残るのは #1 の食い違い。
- 修正案: リージョンのないホストでは #3 の「リージョン不明」扱いにし、クエリは信用しない。残すなら、ボタン文言など別の情報源と一致したときだけ使う。
- 確度: 挙動は実際に走らせて確かめた。影響は、リージョンなしホストのままリダイレクトされずに操作できる画面があるかに依存し、実コンソールでの確認が必要。通常は地域ホストへリダイレクトされ、その時点で host 側の値に置き換わる。

### 6. [低] 赤地の装飾が外部 CSS の読み込みに依存する

- CVSS: `CVSS:3.1/AV:L/AC:H/PR:N/UI:R/S:U/C:N/I:L/A:N` = 2.5。攻撃者不要。
- 根拠: `content.js:138-145`(`<link>` で `content.css` を読み、失敗時は無装飾)、`content.js:49-53`(要素に直接指定するのは `position` / `z-index` / `margin` だけ)、`content.css:3-6`、`content.css:22-23`
- 内容: 背景色 `#d91515`、文字色、`:host { all: initial }` はすべて `content.css` にある。読み込めないと、バナーは背景が透明でページの文字色を継承した素の文字になり、コンソールの内容に重なって読めない。入力欄は残るので機能はするが、警告としての目立ち方を失う。起きる条件は次のとおり。
  - Chrome で拡張を更新・再読み込み・無効化した後、開いたままのタブに残った古いコンテンツスクリプトが初めてバナーを作る場合(`chrome.runtime.getURL` が例外を投げる)。
  - ページの CSP や拡張リソースの取得失敗で `<link>` が読み込めない場合。
  - 読み込み完了までの短い間(毎回)。
- 再現: ハーネスで `chrome.runtime.sendMessage` と `getURL` が「Extension context invalidated」を投げる状態にする → バナーは作られラベルも正しいが、Shadow DOM 内に `<link>` がなく、ホストのインライン指定は位置関係だけ。入力で消す動作は残る。
- 修正案: 色と最低限の体裁を読み込みに依存させない。`content.css` の内容を `content.js` 内の文字列にして `<style>` で Shadow DOM に入れる(`web_accessible_resources` も不要になる)。分けたままにするなら、背景色・文字色・余白だけ `banner.style` に直接書く。
- 確度: コンテキスト無効時に `<link>` なしで作られることは実際に走らせて確かめた。見た目の崩れ方と、コンソールの CSP が `chrome-extension:` / `moz-extension:` のスタイルシートを通すかは実ブラウザでの確認が必要。

### 7. [低] ホスト要素への見た目の上書きを直さない

- CVSS: `CVSS:3.1/AV:L/AC:H/PR:L/UI:R/S:U/C:N/I:L/A:N` = 2.2。攻撃者(または干渉する他の拡張・利用者スタイル)が必要。
- 根拠: `content.js:177-182` と `content.js:211-224`(管理しているプロパティだけ書き戻す)、`content.js:254-258`(`style` / `class` の変更は監視対象外)、`content.css:3-6`(`:host` の指定は外側のスタイルに負ける)、`content.js:224`
- 内容: ホスト要素は `document.body` 直下の素の `div` で、ページ側の DOM に露出している。
  - `opacity` / `visibility` / `transform` / `clip-path` などをインラインで書かれると、`update()` を何度通っても残る。
  - ページや利用者スタイル(ダークテーマ系の拡張など)の `body > div { … !important }` は、`!important` なしのインライン指定と `:host` の指定の両方に勝つ。`display: none !important` を当てられると常時非表示になる。
  - `data-testid="awsc-nav-regions-menu-button"` を持つ最初の要素に `aria-expanded="true"` が付いている間、バナーは `display: none` になる。メニューが開いたままの状態や、同じ属性を持つ別の要素が先にあると隠れ続ける。
  - `<dialog>` の `showModal()`、Popover、全画面表示はトップレイヤーに描かれ、`z-index` 最大でもその下になる。
- 再現: ハーネスでホストに `opacity: 0`、`visibility: hidden !important`、`transform: translateX(-9999px)`、`top: -9999px !important`、`display: none !important` をインラインで書いてから `update()` を走らせる → `top` と `display` は元に戻るが、`opacity` / `visibility` / `transform` は残る。`aria-expanded="true"` にすると `display: none`。
- 成立しない範囲: ホスト要素を `remove()` しても 200ms 後に付け直される(確認済み)。ページ側スクリプトは closed な Shadow DOM の入力欄に触れず、コンテンツスクリプトは隔離ワールドで動くので `attachShadow` の差し替えも効かない。入力の自動埋めと `chrome.storage.session` の書き換えは、ページ側からはできない。他の拡張は `chrome.dom.openOrClosedShadowRoot` で入力欄に届くが、同じ権限を持つ拡張はページ自体を操作できるので、この拡張で防ぐ対象ではない。
- 修正案: インライン指定を `!important` 付きにし、`opacity: 1` / `visibility: visible` / `transform: none` / `clip-path: none` / `display: block` も管理対象に加える。`update()` のたびに `getComputedStyle(host)` で `display` / `visibility` / `opacity` を確かめ、隠れていたらホストを作り直す。可能なら `popover="manual"` + `showPopover()` でトップレイヤーに載せる。
- 確度: インライン書き換えと `aria-expanded` の挙動は実際に走らせて確かめた。スタイルシートの優先順位とトップレイヤーの重なりは CSS 仕様からの推論で、実ブラウザでの確認が必要。

### 8. [低] グローバル判定が固定一覧と 2 言語の文言だけ

- CVSS: `CVSS:3.1/AV:L/AC:H/PR:N/UI:R/S:U/C:N/I:L/A:N` = 2.5。攻撃者不要。
- 根拠: `content.js:13-21`、`content.js:22`、`content.js:68`(パス判定が最優先)、`content.js:72`
- 内容: 誤りは両方向にある。
  - リージョン別の機能に「Global」と出る: パスの先頭セグメントが `iam` なら無条件に Global。IAM コンソール配下にリージョン別の機能(Access Analyzer など)があれば、そこでも Global と表示し、Global を確認済みなら何も出ない。
  - グローバルなサービスにリージョンが出る: 一覧にないサービス(`/support/` など)はホスト名のリージョンを表示する。ボタン文言での補正は `global` と `グローバル` の完全一致だけで、他の表示言語(例: `全球`)では効かない。
- 再現: ハーネスで `https://ap-northeast-1.console.aws.amazon.com/iam/home?region=ap-northeast-1#/access_analyzer` → 「Global」。`https://us-east-1.console.aws.amazon.com/support/home` → 「us-east-1」、ボタン文言が `Global` なら「Global」、`全球` なら「us-east-1」。
- 修正案: パス一覧を最優先にせず、ボタン文言の Global 判定を先にする。パス一覧は、ボタンがまだ描画されていない間の補助に下げる。対応する表示言語の文言を足すか、文言に依存しない属性があればそちらを使う。
- 確度: 判定結果は実際に走らせて確かめた。IAM 配下のリージョン別機能の URL と、各言語でのボタン文言は実コンソールでの確認が必要。

### 9. [情報] 確認状態の鍵がタブ ID だけ

- CVSS: `CVSS:3.1/AV:L/AC:H/PR:N/UI:R/S:U/C:N/I:N/A:N` = 0.0。攻撃者不要。README に書かれた仕様どおりの動作で、脆弱性としては数えない。
- 根拠: `background.js:13`、`content.js:230`
- 内容: 同じタブで別のアカウントに切り替えても(サインアウト → 別アカウント、マルチセッションの切り替え)、リージョンが同じならバナーは出ない。確認に期限もなく、朝に確認したタブは終日バナーなしになる。IAM で Global を確認すると、同じタブの Route 53 / CloudFront / 請求でも出ない。

### 10. [情報] 対象外ドメインと導入直後の既存タブでは無言で無効

- CVSS: `CVSS:3.1/AV:L/AC:H/PR:N/UI:R/S:U/C:N/I:N/A:N` = 0.0。攻撃者不要。
- 根拠: `manifest.json:13`、`README.md:50`
- 内容:
  - 一致パターンは `https://*.console.aws.amazon.com/*` だけ。README は GovCloud と中国リージョンを対象外と書いているが、ほかにも AWS European Sovereign Cloud のコンソールや、`console` を含まないドメインで動くサービス(Lightsail、QuickSight など)が外れる。これらのページでは拡張が動いていないことを示す手がかりがない。
  - Chrome はインストール・有効化の時点で開いているタブにコンテンツスクリプトを入れない。再読み込みするまで、そのタブはバナーなしになる。
  - コンテンツスクリプトは既定の `document_idle` で始まり、復元の応答(最大 1 秒)と 200ms の遅延を待ってから描画する。bfcache からの復元で background が応答しないときは、最大 1 秒間、古い確認状態のままバナーが出ない(ハーネスで 900ms 時点はバナーなし、1100ms 時点で表示を確認)。
- 修正案: README の「制限」に、対象外の具体例と「導入・有効化後は開いているコンソールのタブを再読み込みする」を書く。対象を広げるかは必要が出てからでよい。
- 確度: 一致パターンと遅延は実際に走らせて確かめた、またはコードから読める。各コンソールのドメイン名と Chrome の注入の挙動は実環境での確認が必要。

| プリレンダリングなど `frameId` が 0 でないページ | background が応答せず、保存済みの確認があってもバナーが出る(`background.js:18`) | 実走 |
